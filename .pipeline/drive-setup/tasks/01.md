### Fault 1 — the `ask_*` seam contract is self-contradictory (abort cannot cross `$(...)`)
`ask_value`/`ask_confirm`/`ask_choice` set `setup_abort=1` on read-failure/EOF (drive.sh:204,:217,:233),
but every caller consumes them through command substitution — `impl_transport=$(ask_choice …)`
(setup_defaults:341-351), `dst=$(ask_value TARGET_REPO …)` (setup_target:396). `$(...)` forks a subshell,
so `setup_abort=1` mutates the subshell's copy of the dynamically-scoped variable and never reaches the
parent frame. Every downstream guard — `if [ "$setup_abort" = 1 ]` (setup_defaults:351, setup_target:398)
and setup()'s per-step `[ "$setup_abort" = 0 ]` gates (:437-439) — always reads 0, so EOF/Ctrl-D falls
through to the hardcoded default and writes the file with exit 0. **A function cannot both return its
value on stdout (required by the `$(...)` callers) AND signal abort by mutating a caller variable — the
two are mutually exclusive in bash.** This is an arch contract flaw in the ask_* seam.
Fix direction (task/arch owns): carry abort in the value channel — command-substitution **exit status
does propagate** (`v=$(ask_value …) || { setup_abort=1; return 1; }`), or a sentinel file, or move the
mutating write out of `$()`. Freeze a **real-PTY EOF/Ctrl-D** regression that fails on `a76f838`. (The
current headless `SETUP_YES=1` tests take each helper's early `printf` return *before* `read`, so the
green suite never executes the broken path — that is why the property is violated while tests pass.)

### Fault 2 — no single symlink-refusing write primitive; 3 of ~4 sinks escape
The no-symlink-write guarantee is hand-rolled per-site and applied only to the *final* destinations
(`setup_target` guards `$rf`+`$dst/.pipeline` :403-411; `setup_pboard_block` guards `$rc` :265). The
remaining sinks are unguarded:
- **`.bak` backups** follow a symlink out of the repo: `cp "$rf" "$rf.bak"` (setup_target:413),
  `cp "$DEFAULTS" "$DEFAULTS.bak"` (setup_defaults:378) — the review PoC overwrote an external victim.
- **`setup_defaults` primary write has NO guard**: `printf … > "$DEFAULTS"` (setup_defaults:379) is a
  plain redirect that follows a symlinked `drive.defaults` (setup_target routes through `_atomic_write`;
  setup_defaults does not).
- **`_atomic_write` temp is predictable + non-exclusive**: `tmp="$dir/.setup-aw.$$.$RANDOM.tmp"` then
  `cat > "$tmp"` (drive.sh:254-256) — a pre-created symlink at that path is followed (TOCTOU).
**Root cause: a missing abstraction.** No one "refuse-symlink + O_EXCL temp + atomic rename +
mode-preserving" primitive forces ALL writes (primary + `.bak` + temp, across defaults/roles/pboard)
through it; the guard was added at two sinks and forgotten at the rest.
Fix direction (task/arch owns): introduce that single primitive, route every artifact write through it,
and freeze a **`*.bak -> victim` symlink-escape** case and a **symlinked `drive.defaults`** case (the
current suite freezes only the primary roles.yaml symlink).
